"@recursica/mui-adapter": patch

Fix all broken CSS design-token variable references across the MUI adapter (31 components: Accordion, Autocomplete, Avatar, Badge, Button, Card, Checkbox, Chip, Dropdown, FormControlWrapper, HoverCard, Label, Link, Loader, Menu, Modal, NumberInput, Pagination, Panel, Radio, ReadOnlyField, SegmentedControl, Slider, Stepper, Switch, Tabs, TextArea, TextField, Timeline, Toast, Tooltip). These components referenced UI Kit CSS variables that no longer exist after the token schema restructure (e.g. `colors_background` → `colors_background-color`, per-component hover/disabled tokens replaced by shared brand-state tokens, several components split into item/header/content sub-namespaces). Variable names and patterns were corrected to match the current `recursica_variables_scoped.css` schema, using the already-updated `@recursica/mantine-adapter` as the reference implementation. `npm run analyze-tokens` now passes with zero broken variables.

Also wired up ~39 previously-unused-but-valid tokens across Accordion, Label, Link, Autocomplete, Dropdown, NumberInput, TextField, Menu, SegmentedControl, Timeline, Slider, and Toast (border/elevation, disabled opacity, item-gap/padding, focus-state colors, etc.) that `@recursica/mantine-adapter` already consumed but the MUI implementations didn't — again ported from the mantine reference. Where mantine itself doesn't consume a given token (documented `recursica-ignore` exemption in the reference with a stated rationale), the same documented exemption was mirrored in the MUI file rather than inventing a CSS binding. Two large partial-stub components (Table, DatePicker) and five fully-unimplemented components (Tree, FileInput, FileUpload, TimePicker, TransferList) still have unused tokens and are intentionally out of scope for this change — they need real component-build work, not a token-wiring pass.
