# TimePicker Implementation Notes

## Architecture Overview

Unlike every other input in `mui-adapter`, `TimePicker` wraps `@mui/x-date-pickers`'s `TimePicker` (not a plain `@mui/material` primitive). This was a deliberate choice (Matt Massey, 2026-08-07) over a native `<input type="time">`, in exchange for a real clock/list-based time selection UI, in exchange for a new dependency (`@mui/x-date-pickers` + `dayjs`, both added as optional peer deps + a real `dayjs` dependency).

## `hideAmPm` and the AM/PM composite

By default (`hideAmPm={false}`) this renders a **12-hour field with no native meridiem section, plus a separate AM/PM `<Select>`** next to it — a Recursica-specific design (Matt Massey, 2026-08-07), not something MUI X ships out of the box. `hideAmPm={true}` renders a plain 24-hour field with no AM/PM control at all (the original, simpler shape this component shipped with).

0. **No `variant` prop to force "standard"**: unlike the field-level `variant` this component originally used in #483, `@mui/x-date-pickers` v9's public `TimePicker`/`slotProps.field` API doesn't expose a `variant` prop at all anymore (it's only reachable on an internal `textFieldProps` object this package doesn't surface). The CSS module defensively suppresses **both** the "standard" variant's underline (`::before`/`::after`) and the "outlined" variant's notched-outline, since which one actually renders isn't controllable from here — only one of the two suppressions will ever be doing anything at runtime.
1. **Why not Recursica's own `Dropdown` component**: `Dropdown` wraps its own `FormControlWrapper`/`FormControlLayout` internally (it's meant to be used standalone, with its own label/assistive text). Nesting it inside `TimePicker` — which is already inside a `FormControlWrapper` — would double up `FormControl` wrapping and layout margins. Instead, the AM/PM control uses the same underlying primitive `Dropdown` is built on (`@mui/material`'s `Select`/`MenuItem`), styled locally in this component's own CSS module rather than shared with `Dropdown`'s.
2. **Internal state, unlike every other component here**: every other input in this adapter is a thin pass-through with no internal React state — the wrapped library component owns all interaction state. `TimePicker` is the one exception: because the time field and the AM/PM select both mutate the _same_ conceptual value, something has to reconcile them. `TimePicker.tsx` keeps a `useState<Dayjs | null>` for the full 24-hour internal value, seeded from `value`/`defaultValue`, synced when `value` changes (controlled usage), and updated by both controls. The public `value`/`onChange` API is unaffected — still a plain `"HH:mm"`/`"HH:mm:ss"` string, exactly like before this change.
3. **12-hour field format has no meridiem section on purpose**: `format="hh:mm"` (lowercase `hh`) renders 12-hour digits (1–12) with no `a` (meridiem) token, so there's nothing for the user to toggle within the field itself — meridiem is only ever changed via the separate `<Select>`. Editing just the hour/minute digits preserves whichever meridiem the current internal value already has, since we always pass a fully-formed `Dayjs` value back into the field (never letting it manage its own uncontrolled state) — this only holds because `TimePicker` is always operated in this internally-controlled mode; verify this assumption still holds if the field's controlled/uncontrolled behavior changes in a future `@mui/x-date-pickers` upgrade.
4. **Value/onChange boundary**: unchanged — plain `"HH:mm"`/`"HH:mm:ss"` strings; `dayjs` never leaks into the public API.
5. **Read-Only Implementation**: `readOnlyType="text"`, matching `DatePicker`'s convention.
6. **Known limitation — the popup clock/list view is unstyled**: this pass covers the closed-state field and the AM/PM select only. The open dropdown (digital clock list, depending on `views`) still renders with MUI's default theme, not Recursica tokens — there's no Figma-exported token set for it (mirrors the same category of gap `DatePicker`'s calendar popover has in `mantine-adapter`). Revisit once there's a design spec for it.
