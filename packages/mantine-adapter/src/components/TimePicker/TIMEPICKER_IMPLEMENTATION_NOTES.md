# TimePicker Implementation Notes

## Architecture Overview

`TimePicker` wraps `@mantine/dates`'s own `TimePicker` component (not `TimeInput` — a separate, more advanced component in the same package that natively supports 12-hour format, hour/minute/second `SpinInput`s, and an AM/PM select). This was a deliberate switch (Matt Massey, 2026-08-07) after discovering Mantine already ships exactly the composite this component needs, rather than building hour/minute segments and an AM/PM control from scratch.

## Structural Constraints

1. **`hideAmPm` is Recursica-specific, not a Mantine concept**: by default (`hideAmPm={false}`) this component renders in **12-hour format with an AM/PM selector** — a deliberate deviation from the underlying library's own default (`24h`), because the Recursica UI Kit's design calls for a dedicated AM/PM control next to the time input. `hideAmPm={true}` switches to `format="24h"`, matching the underlying library's own default with no AM/PM control at all. See USAGE.md.
2. **The AM/PM control is a native `<select>`, not a custom `Dropdown`**: Mantine's `TimePicker` only exposes `amPmSelectProps` (native `<select>` attribute passthrough), not a way to swap in an arbitrary custom component for that slot. This means the AM/PM control does **not** pixel-match Recursica's own `Dropdown` component — native `<select>` elements have limited stylability (especially their open option list, which is OS-rendered). Styling here is limited to what CSS can reach on the closed `<select>` element itself, via the shared `.field` styles-API slot (same slot hour/minute/second `SpinInput`s use).
3. **Different Styles API shape than every other input in this adapter**: `TimeInput`/`TextField`/`DatePicker` all use Mantine's generic `__InputStylesNames` (`wrapper`, `input`, `section`). `TimePicker` adds its own additional named slots (`fieldsRoot`, `fieldsGroup`, `field`, plus dropdown/preset-list slots we don't use). `classNames` here targets `wrapper` (the outer bordered box, via `InputBase` internally), `fieldsGroup` (the flex row holding every segment), and `field` (each individual hour/minute/second/AM-PM segment) — there is no single `.input` class to target since there's no single `<input>` element.
4. **No icon slot**: unlike `TextField`/`DatePicker`, this composite has no leading/trailing icon concept. The `time-picker` token set's `icon-size`/`icon-color`/`icon-text-gap` tokens are exempted (`recursica-ignore`) rather than wired up, since there's nothing to attach them to.
5. **`withDropdown={false}`**: Mantine's `TimePicker` also supports an optional popover with a scrollable time-presets list (`withDropdown`, `presets`). Not used here — Matt's ask was specifically for the AM/PM control, not an additional time-list popup. Revisit if that's wanted later.
6. **`min`/`max` naming**: Mantine's `TimePicker` names these props `min`/`max` (not `minTime`/`maxTime` like `TimeInput`) — mapped directly from the shared `RecursicaTimePickerProps` contract's `minTime`/`maxTime` at the component boundary.
7. **Read-Only Implementation**: `readOnlyType="text"`, matching `DatePicker`'s convention — unchanged from the prior `TimeInput`-based version.
